I'd like to start my reflection with a brief introduction to new strings I learned in this module. For example, the "&&" string can
 be used to run a second Linux command if and only if the first command succeeds. I practiced with a familiar concept using nano to create and edit
python files directly in the terminal. As for Git, I learned that Git contains branches that allow several versions of a project to be updated seperately.
The value I see in this is that it is useful for testing edits without diluting the main version. During the merge, I ran into a problem with the
main branch and the feature/refactor branch because they both had conflicting modifications to the same line of code.
I fixed the issue, by manually keeping the np.cos change from the main and then the "avg" from the feature branch. I was then able to stage and commit 
the resolved file. Staging with the git add command allowed me to include the current version of the file in my next snapshot, while git commit actually 
saves that prepared snapshot into the Git history.
